# OpenSandbox 1.1.0

统一伞形发布线的首个稳定版本：单一平台版本 —— `1.1.0` —— 覆盖 server、组件镜像、chart、CLI 和所有已发布的 SDK，从单一提交切出并固定在一份签名的 BOM 中（版本号从 `1.1.0` 起步；`1.0.0` 已被旧版发布消耗，因此按伞形治理 OSEP 的设计刻意跳过）。所有仍在使用旧版按组件版本的用户都应升级；旧版标签命名空间已被冻结。由于这是首次伞形切版，各章节的基线不同 —— controller 自其 5 月的 `v0.2.0` 发布跃升，ingress 自 7 月，JavaScript/C#/Go SDK 自其 7 月的发布 —— 因此这些章节一次性列出了数月的变更。

## 亮点

- 首个统一伞形发布：每个制品都在 `1.1.0` 下随标签 `release-1.1.0` 交付，并以 Sigstore 签名的 BOM 作为摘要的权威来源
- Fast Sandbox 集成的首次发布：Firecracker microVM 运行时由 FastPath fleets 后端承载，支持暂停/恢复、ingress FastPath 路由，以及全部五个 SDK 中的 fsb 模板管理
- 快照持久化新增可选的 PostgreSQL 存储并支持多进程 HA 与 SQLite 迁移命令；sandbox 新增 preStart/periodic 生命周期钩子

## Server

- 新增 FastPath fleets 生命周期后端：通过 FastPath v2 提供创建、续期、删除和状态映射，并支持带异步 202 语义和 UID fencing 的端到端 fsb 暂停/恢复（[#1703](https://github.com/opensandbox-group/OpenSandbox/pull/1703) [#1844](https://github.com/opensandbox-group/OpenSandbox/pull/1844)）
- 通过按命名空间的 watch（而非阻塞式轮询）统一快照状态，并新增 fast-sandbox 快照支持（[#1846](https://github.com/opensandbox-group/OpenSandbox/pull/1846)）
- 新增带连接池和 CAS 语义的可选 PostgreSQL 快照存储、用于迁移 SQLite 记录的一次性 `migrate-snapshots` 命令，以及 Kubernetes 上快照创建/恢复/删除的多进程 HA 协调（[#1653](https://github.com/opensandbox-group/OpenSandbox/pull/1653) [#1670](https://github.com/opensandbox-group/OpenSandbox/pull/1670) [#1724](https://github.com/opensandbox-group/OpenSandbox/pull/1724)）
- 传输 sandbox 生命周期钩子（OSEP-0020）：创建请求接受 `preStart` 和 `periodic` 钩子，经校验后序列化到 Kubernetes 工作负载的保留环境变量中；Docker provider 暂不支持生命周期请求（[#1589](https://github.com/opensandbox-group/OpenSandbox/pull/1589) [#1542](https://github.com/opensandbox-group/OpenSandbox/pull/1542)）
- 在既有的日志/事件收集器之上实现稳定且作用域受限的诊断 API，提供 `logs:container|all` 和 `events:runtime|lifecycle|all` 作用域、部分作用域时的显式告警、未知作用域返回 `400 DIAGNOSTICS_SCOPE_UNSUPPORTED`，以及向后兼容的纯文本响应（[#1553](https://github.com/opensandbox-group/OpenSandbox/pull/1553)）
- 通过 OTLP 从 server 导出通用 HTTP 请求指标（请求速率、错误速率、延迟），补充 SDK 上报的创建耗时直方图（[#1561](https://github.com/opensandbox-group/OpenSandbox/pull/1561)）
- 在持久化之前拒绝不支持的 gVisor（`runsc`）快照，返回 `409 SNAPSHOT::UNSUPPORTED_RUNTIME`（[#1720](https://github.com/opensandbox-group/OpenSandbox/pull/1720)）
- 通过 `[egress.resources]` 支持 Kubernetes egress sidecar 的独立资源请求/限制（[#1620](https://github.com/opensandbox-group/OpenSandbox/pull/1620)），新增 `[egress] otlp_endpoint` 使 sidecar 在两种运行时上都向 OpenTelemetry collector 导出指标（[#1753](https://github.com/opensandbox-group/OpenSandbox/pull/1753)），sidecar 与 sandbox 一起暂停和恢复（[#1441](https://github.com/opensandbox-group/OpenSandbox/pull/1441)），sidecar 就绪等待时间可通过 `[egress] timeout_seconds` 配置（[#1522](https://github.com/opensandbox-group/OpenSandbox/pull/1522)），并在 server 端注入 `OPENSANDBOX_EGRESS_SANDBOX_ID`，使 sidecar 遥测无法再被请求 env 伪造（[#1381](https://github.com/opensandbox-group/OpenSandbox/pull/1381)）
- 在 agent-sandbox provider 的创建请求中支持 `image.auth`，使用随 Sandbox CR 一起被垃圾回收的按 sandbox 拉取凭证（[#1789](https://github.com/opensandbox-group/OpenSandbox/pull/1789)）

- 通过 `[proxy] resolve_internal` 使反向代理的内部解析可配置，用于无法路由到 Docker 桥接 IP 的部署（[#1631](https://github.com/opensandbox-group/OpenSandbox/pull/1631)）

- 新增 Docker 运行时级别的 `sandbox_env` 和 `sandbox_binds` 配置，使 Docker 在 CA 证书包、代理和挂载方面与 Kubernetes pod 模板达到同等能力（[#1303](https://github.com/opensandbox-group/OpenSandbox/pull/1303)）

- 稳定 pool 调度：pool-assign 中的容量谓词、修复 pool 扩缩容预期卡住的问题，以及扩缩容稳定性（[#1143](https://github.com/opensandbox-group/OpenSandbox/pull/1143) [#906](https://github.com/opensandbox-group/OpenSandbox/pull/906) [#1425](https://github.com/opensandbox-group/OpenSandbox/pull/1425)）

- 通过 Pool 回收策略支持随 sandbox 一并删除 PVC（可选启用）（[#880](https://github.com/opensandbox-group/OpenSandbox/pull/880)）
- 为 controller 新增 containerd socket 路径标志（[#859](https://github.com/opensandbox-group/OpenSandbox/pull/859)）
- 重构 image committer：可复用的 `pkg/imagecommitter` 接口及 containerd 原生默认实现、源仓库认证、自签名/纯 HTTP 传输策略，以及由操作者控制的 Job 模板覆盖（[#1431](https://github.com/opensandbox-group/OpenSandbox/pull/1431)），并为经认证的 registry 代理新增拉取凭证（[#1300](https://github.com/opensandbox-group/OpenSandbox/pull/1300)）

## 升级与兼容性

- Breaking：agent-sandbox provider 和 ingress 要求 `agents.x-k8s.io/v1beta1`（agent-sandbox v1.0.0）；升级前请安装 beta CRD/controller —— 参见 [#1763](https://github.com/opensandbox-group/OpenSandbox/pull/1763) 中的迁移指南
- 对 chart 用户为 Breaking：chart 已迁移到 `manifests/charts/`（[#1857](https://github.com/opensandbox-group/OpenSandbox/pull/1857)）
- 配置：移除了 beta 的 `informer_enabled` 开关；基于 informer 的缓存现在是唯一的 Kubernetes 读取路径（它此前已是默认值，升级时移除该键即可）（[#1926](https://github.com/opensandbox-group/OpenSandbox/pull/1926)）
- 行为变更：code-interpreter 创建默认阻塞直至严格就绪（[#1754](https://github.com/opensandbox-group/OpenSandbox/pull/1754)）；如果你依赖之前的宽松行为，请显式设置
- 行为变更：生命周期钩子在创建时被校验，且本版本在 Docker provider 上被拒绝（[#1589](https://github.com/opensandbox-group/OpenSandbox/pull/1589)）
- Go module：`poolredis` 已合并进父模块 `github.com/alibaba/OpenSandbox/sdks/sandbox/go`，导入路径不变；单一伴随标签现在同时为两者确定版本（[#1903](https://github.com/opensandbox-group/OpenSandbox/pull/1903)）
- 镜像：`opensandbox/<component>:release-1.1.0`（全部三个仓库）
- 软件包：server / CLI / SDKs 均为 `1.1.0`
- Chart：从该标签渲染（`helm template ./manifests/charts/opensandbox`）
- Kubernetes：支持范围 v1.21 – v1.34（chart 声明 `kubeVersion: ">=1.21.1-0"`）
- 版本偏差：server ↔ CLI/SDK 同一版本线受支持；±1 个 minor 会告警

## 安装

```bash
# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
git checkout release-1.1.0
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.1.0            # Python
npm install @alibaba-group/opensandbox@1.1.0   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.1.0")
dotnet add package Alibaba.OpenSandbox --version 1.1.0
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.1.0

# Run the server locally
uvx opensandbox-server==1.1.0
```
