# OpenSandbox 1.1.1

`1.1.1` 补丁版本线的稳定切版：修复损坏的 `1.1.0` server wheel —— hatchling 的 VCS 排除过滤将已提交的 FastPath gRPC 桩（stub）从 PyPI 包中静默丢弃，导致所有 `1.1.0` 版本的 `opensandbox-server` 安装在导入时报错；PyPI 不可变，因此修复落在本版本线（[#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)）。SDK/CLI/server 软件包以 `1.1.1` 发布（`1.1.1-rc.1` 仅发布了镜像）。所有使用 `1.1.0` 的用户都应升级。以下每个章节的基线均为 `release-1.1.0`。

## 亮点

- 修复 `1.1.0` server wheel：FastPath 桩现已随包交付，安装后可正常导入；SDK/CLI/server 软件包以 `1.1.1` 发布（[#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)）
- 身份绑定的文件系统操作：execd 以显式的 Linux UID/GID 执行文件 API，五个 SDK 均提供 `FilesWithIdentity`/`files_with_identity`；隔离会话获得多个独立 overlay 挂载（[#2070](https://github.com/opensandbox-group/OpenSandbox/pull/2070) [#2093](https://github.com/opensandbox-group/OpenSandbox/pull/2093) [#2094](https://github.com/opensandbox-group/OpenSandbox/pull/2094) [#2095](https://github.com/opensandbox-group/OpenSandbox/pull/2095) [#2096](https://github.com/opensandbox-group/OpenSandbox/pull/2096) [#2097](https://github.com/opensandbox-group/OpenSandbox/pull/2097) [#2032](https://github.com/opensandbox-group/OpenSandbox/pull/2032)）
- Server 加固：快照创建在持久化之前先提交运行时对象，使早期读取不会映射到 `Failed`；被代理的后端失败映射为 502/504 而非通用的 500；诊断功能可用于 pool 化 sandbox（[#2098](https://github.com/opensandbox-group/OpenSandbox/pull/2098) [#2077](https://github.com/opensandbox-group/OpenSandbox/pull/2077) [#2084](https://github.com/opensandbox-group/OpenSandbox/pull/2084) [#2104](https://github.com/opensandbox-group/OpenSandbox/pull/2104)）

## Server

- 通过桥接到 `agents.x-k8s.io/v1beta1` 上的 `spec.operatingMode`（`Running`/`Suspended`）实现 agent-sandbox provider 的暂停/恢复，具备状态推导（`Paused`/`Pausing`/`Resuming`/`Terminated`）以及无效转换时的 409；此前两个端点均返回"不支持"（[#1975](https://github.com/opensandbox-group/OpenSandbox/pull/1975)）
- 隔离共享同一 Kubernetes 命名空间的租户：创建时打上 `opensandbox.io/tenant` 标签，list/get/delete/pause/resume/proxy 会以 404 隐藏其他租户的带标签 sandbox，而未打标签的旧 sandbox 在过期前保持可见；同时新增用于 ServiceAccount CA 不匹配场景的 `kubernetes.insecure_skip_tls_verify`（[#1973](https://github.com/opensandbox-group/OpenSandbox/pull/1973)）
- 修复多租户模式下 server 重启后续期意图（renew-intent）被静默丢弃的问题：解析器现在回退到集群级标签查询，配备 403 熔断器与结构化告警；在可验证时信任来自意图载荷中 ingress 观测到的命名空间；单租户部署的解析永远不会超出所配置的命名空间（[#1819](https://github.com/opensandbox-group/OpenSandbox/pull/1819)）
- 新增 `[docker] publish_host`，将桥接模式的 sandbox 端口发布到单个主机地址（默认 `0.0.0.0` 不变）—— 使用 `127.0.0.1` 或 Docker 桥接网关时，无令牌的 execd 端口不再落在公共网络接口上（[#1954](https://github.com/opensandbox-group/OpenSandbox/pull/1954)）
- 新增类型化、仅管理员可用的 `[egress.upstream_proxy]` 配置节（URL + 可选授权，加载时校验），在 Docker 和 Kubernetes 上为 sidecar 注入链式上游 CONNECT 代理；当所请求的 `networkPolicy` 不兼容时以 fail-closed 的 400 拒绝；密钥值不再在配置校验错误中被回显（[#1999](https://github.com/opensandbox-group/OpenSandbox/pull/1999)）；另新增 `ca_cert_path`（Docker）和 `ca_secret_name`（Kubernetes），使由私有 CA 签名的 `https://` 代理无需替换系统信任存储即可被信任 —— 该 PEM 会在 sidecar 中增补 `/etc/ssl/certs`（[#2030](https://github.com/opensandbox-group/OpenSandbox/pull/2030)）
- 使 k8s/fsb 上的快照创建对早期读取者无竞态：`POST /sandboxes/{id}/snapshots` 现在在持久化 `Creating` 行之前先创建运行时对象（SandboxSnapshot CR / fsb 提交）并直接返回而不排队 worker，因此读取时同步不再能把尚未创建的对象映射为 `Failed` —— 包括在其他 HA 副本上；恢复会内联重新提交卡住的行（[#2098](https://github.com/opensandbox-group/OpenSandbox/pull/2098)），修复了客户端在创建后立即轮询会将该行永久翻转为 `Failed` 的窗口（[#2077](https://github.com/opensandbox-group/OpenSandbox/pull/2077)）
- 将被代理的后端失败映射为有意义的状态：读写超时返回 504 `BACKEND_TIMEOUT`，响应中途的重置和协议错误返回 502 `BACKEND_RESPONSE_FAILED`，连接失败仍保持 502 `BACKEND_CONNECTION_FAILED` —— 请求中途死掉的 sandbox 不再被误认为 server 缺陷（[#2084](https://github.com/opensandbox-group/OpenSandbox/pull/2084)）
- 为 k8s 诊断找到 pool 分配的 Pod：pool 化的 BatchSandbox 不携带 `opensandbox.io/id` pod 标签，此前所有 logs/events/inspect 调用都返回 404；查找现在会回退到工作负载 `alloc-status` 注解中列出的 Pod（[#2104](https://github.com/opensandbox-group/OpenSandbox/pull/2104)）
- 当创建在供给块执行之前失败时（镜像拉取、凭证/上游代理检查、Windows 前置条件、OSSFS 准备），移除自动创建的 Docker 卷 —— 拼错的镜像名不再泄漏它触发的 PVC（[#2103](https://github.com/opensandbox-group/OpenSandbox/pull/2103)）
- 将删除中的 pool 化/任务模式 BatchSandbox 报告为 `Stopping`/`DELETING`：`metadata.deletionTimestamp` 现在优先于运行时状态发布，因此在终结期间 Pod 变为 not-ready 的 sandbox 不再翻转回 `Pending`/`CREATING`（[#2122](https://github.com/opensandbox-group/OpenSandbox/pull/2122))
- 阻止 Docker 元数据 PATCH 复活已删除的键：`patch()` 现在从 override 文件出发（与 `get()` 一致），而不是重新合并容器标签，因此 `{"env": null}` 保持删除状态，被清空的 override 文件也不会恢复原始标签（[#2065](https://github.com/opensandbox-group/OpenSandbox/pull/2065)）
- 在模板创建时接受 `env` 并将其烘焙进 fast-sandbox 黄金镜像（`/etc/sandbox-init.env`，继承源镜像的 OCI `Config.Env`），弥补了 `SandboxTemplate.spec.envs` 存在但生命周期 API 拒绝它的缺口；全部 SDK 均支持（[#1984](https://github.com/opensandbox-group/OpenSandbox/pull/1984)）
- Kubernetes 创建等待改由 informer watch 事件唤醒，而非固定的 1 秒轮询，将预热 pool 的创建延迟从约 1 秒降至数十毫秒，同时保留轮询回退（[#1996](https://github.com/opensandbox-group/OpenSandbox/pull/1996)）
- 通过强制包含绕过 hatchling 的 VCS 排除，将已提交的 FastPath gRPC 桩打进 server wheel，并在发布工作流中于发布前对构建出的 wheel 做冒烟导入 —— 这就是 `1.1.0` 安装期损坏的修复（[#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)）
- 修复 Helm RBAC 和 fsb 快照运行时中 Fast Sandbox 快照 CR 的复数形式（`sandboxsnapshots`），此前 `sandboxesnapshots` 可能因缺少 RBAC 而导致 list/watch 失败（[#1972](https://github.com/opensandbox-group/OpenSandbox/pull/1972)）
- 将底层 FastPath 错误消息穿透到 429 容量映射中（保留状态与 `Retry-After`，新增 `cause` 字段），使准入/运行时故障（如 KVM 设备损坏）不再被掩盖为 pool 容量耗尽，并在映射前以 warn 级别记录原始错误（[#2001](https://github.com/opensandbox-group/OpenSandbox/pull/2001)）
- 澄清续期契约：`renew-expiration` 可以缩短、保持或延长过期时间（任何未来的目标时间均有效），而 `max_sandbox_timeout_seconds` 仅限制创建，不限制续期或总生命周期 —— 文档与 SDK 参考已对齐，并在 Docker、Kubernetes 和 FastSandbox 上具备回归覆盖（[#2087](https://github.com/opensandbox-group/OpenSandbox/pull/2087)）
- 修复 Docker 边缘情况：对已暂停 sandbox 的重复暂停请求按文档返回 409，而不是把 Docker 的"已暂停"以 500 呈现（[#2023](https://github.com/opensandbox-group/OpenSandbox/pull/2023)）；仅对选择启用隔离扩展的 sandbox 清除 Docker 的 masked/只读系统路径，使嵌套的 Bubblewrap 能挂载私有 procfs（[#1982](https://github.com/opensandbox-group/OpenSandbox/pull/1982)）

## SDKs

- 端到端新增身份绑定的文件系统操作：execd 增加附加的 `/v1/filesystem/{uid}/{gid}` 路由，由按请求启动、以显式凭证和账户派生的补充组运行的 worker 进程承载（fail-closed，既有路由不变），并且每个 sandbox SDK 都暴露了它 —— Python `files_with_identity`、JavaScript `filesWithIdentity`、Kotlin `filesWithIdentity`、C# `FilesWithIdentity`、Go `FilesWithIdentity` —— 使 Linux 在实际访问时检查所选用户的权限；身份选择应属于可信后端，此功能强制的是文件系统权限，并不构成租户隔离边界（[#2070](https://github.com/opensandbox-group/OpenSandbox/pull/2070) [#2093](https://github.com/opensandbox-group/OpenSandbox/pull/2093) [#2094](https://github.com/opensandbox-group/OpenSandbox/pull/2094) [#2095](https://github.com/opensandbox-group/OpenSandbox/pull/2095) [#2096](https://github.com/opensandbox-group/OpenSandbox/pull/2096) [#2097](https://github.com/opensandbox-group/OpenSandbox/pull/2097)）
- 在 API 和全部五个 SDK 中为隔离会话暴露多个独立 overlay 挂载：`CreateIsolatedSessionRequest.overlays`（`{path, mode, persist}`），支持独立的由主机跟踪或临时 tmpfs 的 upper，`workspace` 保留为语法糖，`SessionState` 回显规范化列表 —— 完成 [#2021](https://github.com/opensandbox-group/OpenSandbox/pull/2021) 的内部地基（[#2032](https://github.com/opensandbox-group/OpenSandbox/pull/2032)）
- 在全部五个 sandbox SDK（Python async/sync、JavaScript、Kotlin/Java、Go、C#）中新增 `commands.setEnv`，用于持久化的运行时环境变量注入：以运行时精确的序列化将 `KEY=VALUE` 追加到 sandbox env 文件，进行本地 key/NUL 校验，并在 `EXECD_ENVS` 未设置时大声失败（[#2013](https://github.com/opensandbox-group/OpenSandbox/pull/2013)）
- 跨 sandbox、code-interpreter 和 MCP SDK 的系统性跨语言审计清理：Go 重试退避坍缩为零延迟且丢失会话 `cwd`；Python 隔离会话忽略 `encoding` 且就绪预算报告过期错误；JS resume 共享并杀死源 sandbox 的传输；Kotlin codes 运行丢弃所有 SSE 帧事件且从不设置 `exitCode`；C# create 在全新 sandbox 404 时失败且空响应体引发 NRE；MCP 的按调用关闭会拆除 server 级共享传输 —— 每一项都附带回归测试修复（[#2020](https://github.com/opensandbox-group/OpenSandbox/pull/2020)）
- 全部五个 SDK 支持模板创建时的 `env`，与 server 端的黄金镜像烘焙保持一致（[#1984](https://github.com/opensandbox-group/OpenSandbox/pull/1984)）
- 跨语言对齐后台命令流完成语义：随着 execd 移除固定的完成延迟，Go、Kotlin 和 C# 中的后台结果收集现在与 Python 和 JavaScript 一样在启动确认时返回，而不是等待 EOF 并推断退出码为 0 —— 请查询命令状态以获得最终结果；前台调用对旧 server 仍读取到 EOF（[#1825](https://github.com/opensandbox-group/OpenSandbox/pull/1825)）

### Python

- 对 `create_session` 和 `delete_session` 的错误响应抛出异常：两者此前都把解析后的模型传给错误处理器（而它需要原始状态），导致 400/404/500 以 `None` 作为成功返回、未知状态以虚假的 `status_code=200` 抛出 —— CLI 可能对一个从未存在的会话打印"Deleted session"（[#2066](https://github.com/opensandbox-group/OpenSandbox/pull/2066)）
- 在 `ConnectionConfig`/`ConnectionConfigSync` 上暴露 `follow_redirects`，并传播到所有手写的 async/sync httpx 客户端，包括 SSE 客户端和生成的客户端包装器（[#1123](https://github.com/opensandbox-group/OpenSandbox/pull/1123)）
- 当就绪截止时间在请求中途到期时保留最后一个真实的端点错误：预算不再把自身的 `SandboxReadyTimeoutException` 记录为 `last_error`，因此像 `KUBERNETES::POD_IP_NOT_AVAILABLE` 这样的原因不再被掩盖为普通超时（[#2121](https://github.com/opensandbox-group/OpenSandbox/pull/2121)）
- 在 server-proxy 模式下认证 Code Interpreter 请求：上下文创建和流式代码执行现在像 sandbox 文件请求一样附加 API 密钥，修复来自同一代理的 401（[#2125](https://github.com/opensandbox-group/OpenSandbox/pull/2125)）
- 对 `SandboxPoolSync.shutdown()` 的拆除做串行化：并发的 shutdown（或 shutdown 与 `start()` 竞态）可能把 warmup 事件循环关闭两次；拆除现在在专用锁下是幂等的（[#2041](https://github.com/opensandbox-group/OpenSandbox/pull/2041)）
- 让共享的 warmup 事件循环成为孤儿而不是在 warmup 进行中关闭它：当有界的排空等待结束时 warmup 仍在运行，shutdown 会让循环保持存活，使进行中的 warmup 完成并清理其 sandbox，而不是销毁挂起的任务并跳过清理（[#2142](https://github.com/opensandbox-group/OpenSandbox/pull/2142)）
- MCP：将预期的 OpenSandbox 校验映射到 MCP 2.x 的 `ToolError`，使客户端获得可操作的消息而非通用的"Error executing tool"（[#2108](https://github.com/opensandbox-group/OpenSandbox/pull/2108)）

### JavaScript

- 将空响应体的非 2xx 响应视为错误：openapi-fetch 对 `Content-Length: 0`/204/HEAD 响应不设置 `error`，因此来自网关的空 404/502/503 会让 `deleteSandbox`、`pauseSandbox` 和文件删除在 sandbox 与 code-interpreter 两个包中看起来都成功了（[#2101](https://github.com/opensandbox-group/OpenSandbox/pull/2101)）

### C#

- 通过 `sandbox.FilesWithIdentity(uid, gid)` 实现身份绑定的文件系统操作 —— 参见上文跨 SDK 条目（[#2096](https://github.com/opensandbox-group/OpenSandbox/pull/2096)）

### Go

- 通过 `sandbox.FilesWithIdentity(uid, gid)` 实现身份绑定的文件系统操作 —— 参见上文跨 SDK 条目（[#2097](https://github.com/opensandbox-group/OpenSandbox/pull/2097)）
- 为此前未覆盖的面补充文档：文件操作、卷挂载（`host`/`pvc`/`ossfs`）、完整的模板工作流、带自定义健康检查的 `WaitUntilReady`，以及 `SandboxManager`（[#2024](https://github.com/opensandbox-group/OpenSandbox/pull/2024)）

## Controller

- 在 `opensandbox/controller` meter 上新增 OpenTelemetry 分配路径指标：pool 分配调度、alloc 状态持久化和分配结果同步的时长直方图，带 namespace/pool/success 属性，通过 OTLP 导出（[#2014](https://github.com/opensandbox-group/OpenSandbox/pull/2014)）
- 为 pool-assign 面向自定义扩展做准备：`poolassign` 之下的 `Predicate` 接口和谓词方法现已导出 —— 该包仍在 `kubernetes/internal/` 之下，外部 Go module 暂不能导入（[#2037](https://github.com/opensandbox-group/OpenSandbox/pull/2037)）
- 在初始启动期间自动替换卡在供给失败中的 BatchSandbox Pod：一直处于 `ImagePullBackOff`/`ErrImagePull` 的 never-Ready Pod 在超过阈值后被删除，以便调度器逃离坏节点（一次磁盘写满曾让一个生产 fleet 卡住 114 个 sandbox），并带有按 sandbox、按世代的替换预算和 `PodRecoveryLimitReached` 告警；永久损坏的镜像会被跳过（[#1961](https://github.com/opensandbox-group/OpenSandbox/pull/1961)）
- 支持自定义快照镜像 URI 模板：`--snapshot-image-uri-template` / `controller.snapshot.imageURITemplate` 以快照/sandbox/容器/命名空间元数据和 `date`/`dateInZone` 辅助函数命名 rootfs 与 QEMU VM 状态目标，并在创建 Job 之前校验（无效引用、重复目标）；留空则保持既有命名（[#2004](https://github.com/opensandbox-group/OpenSandbox/pull/2004)）
- 修复仅凭非空 IP 就准入 Pod 的 free-pod 谓词：任务调度器曾把任务绑定到 Kubernetes 标记为 `NotReady`（仍在启动或重启中）的 Pod 上，分配 POST 失败且无重试，还跳过了健康的兄弟 Pod；现在与其他谓词一样要求就绪（[#2138](https://github.com/opensandbox-group/OpenSandbox/pull/2138)）
- 在释放期间状态查询失败时保留最后已知的任务状态：一次 `/getTasks` 超时不再把 `releasing` 任务标记为已消失 —— 那会跳过 `Set(nil)`、跳过 postStop 钩子，并使 controller 在任务仍在运行时丢弃清理 finalizer 或把 Pod 归还给 pool（[#2067](https://github.com/opensandbox-group/OpenSandbox/pull/2067)）
- 对已处于 `Paused` 的 BatchSandbox 跳过暂停分发：续期已暂停的 sandbox 会提升其 generation 并重新触发 `handlePause`，而它需要一个运行中的源 Pod，导致 sandbox 走向 `Failed`/`PauseFailed`（[#2082](https://github.com/opensandbox-group/OpenSandbox/pull/2082)）
- 修复 image-committer 死锁：通过 cgroup v2 freeze 暂停 QEMU 容器时永远无法完成（KVM worker 内核线程永远到不了 `frozen`），修复方式是对已通过 QMP 暂停的 QEMU 容器跳过冗余的 freeze，并以 `--pause=false` 提交（[#1986](https://github.com/opensandbox-group/OpenSandbox/pull/1986)）

## Execd

- 以显式的 Linux 身份执行普通文件系统操作：附加的 `/v1/filesystem/{uid}/{gid}` 路由按请求派生 worker 进程，使用所选 uid/gid 及账户派生的补充组，在不支持的平台 fail-closed；既有路由保持其当前身份 —— 面向 SDK 的后续跟进随同一发布交付（[#2070](https://github.com/opensandbox-group/OpenSandbox/pull/2070)）
- 暴露公共的隔离会话 overlays API（校验、与旧 `workspace` 的规范合并、按 overlay 的分配器指派）—— 详情与 SDK 支持见 SDKs 章节（[#2032](https://github.com/opensandbox-group/OpenSandbox/pull/2032)）
- 为 overlay 会话提供其可移除子树之外的持久清理身份（`<upper_root>/.execd-cleanup/<session-id>`）：启动恢复只移除完全匹配的目录，部分删除或丢失的记录会在进程内或跨重启重试，而不是遗留 upper 目录成为孤儿（[#2107](https://github.com/opensandbox-group/OpenSandbox/pull/2107)）
- 让已完成后台命令的子进程继续运行：`Wait` 之后的 context 取消不再 SIGKILL 整个进程组，因此后台化的 `nohup ./server &` 能在脚本结束后存活 —— 取消和超时仍会杀掉整个组（[#2074](https://github.com/opensandbox-group/OpenSandbox/pull/2074)）
- 当 bash 会话运行超时时杀死整个进程组：此前只杀死 bash 本身，因此 `(sleep 2; …)` 的子进程会让运行在截止时间之后继续挂起（[#2079](https://github.com/opensandbox-group/OpenSandbox/pull/2079)）
- 在前台 `/command` 的 stdout/stderr 事件文本中保留 `\n`/`\r` 字节，使拼接的事件能重建命令的换行符，包括空行和末尾未终止的片段；Python SDK 面向显示的 `Execution.text` 和 stderr 摘要在 CRLF 跨事件到达时不再插入多余的空行，而原始的 `logs.stdout`/`logs.stderr` 保持其原始文本（[#2033](https://github.com/opensandbox-group/OpenSandbox/pull/2033)）
- 移除每次运行的 bash 会话脚本文件（`execd_bash_*.sh`），它保留了每个会话环境变量的副本 —— 包括密钥 —— 任何后续以同一用户运行的命令都可读取（[#2076](https://github.com/opensandbox-group/OpenSandbox/pull/2076)）
- 在计算长度之前钳制 HTTP `Range` 的末尾：`bytes=0-9223372036854775807` 会溢出成负长度并以损坏的 `Content-Range`/`Content-Length` 且无响应体回答 206，普通下载与隔离会话下载均受影响（[#2089](https://github.com/opensandbox-group/OpenSandbox/pull/2089)）
- 移除命令完成后固定的 1 秒延迟，将终端事件到返回的中位延迟从约 1000 ms 降至亚毫秒级，同时保留输出冲刷和心跳清理（[#1825](https://github.com/opensandbox-group/OpenSandbox/pull/1825)）
- 停止在 info 级别记录每一个 stdout/stderr 数据块 —— 在输出密集的工作负载中它占 execd 日志量的 99.8%（[#1906](https://github.com/opensandbox-group/OpenSandbox/pull/1906)）

## 升级与兼容性

- PyPI 上的 `1.1.0` server 包在导入时即损坏且无法替换（PyPI 不可变）—— 请升级到本版本线；参见 [#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)
- 行为变更：HTTP 代理将后端读写超时映射为 504、响应中途失败映射为 502，并带类型化错误码，而非通用的 500；各 SDK 的默认重试配置对新 504 不同 —— Go SDK 的 `DefaultRetryConfig` 对 504 像 502/503 一样重试，而 Python 默认只重试 502/503（[#2084](https://github.com/opensandbox-group/OpenSandbox/pull/2084)）
- 行为变更：已完成后台命令遗留的子进程在其退出后继续运行，与前台路径一致；取消和超时仍会杀掉整个组（[#2074](https://github.com/opensandbox-group/OpenSandbox/pull/2074)）
- 行为变更：k8s/fsb 上的快照创建在持久化之前先提交运行时对象，且恢复会内联重新提交；轮询客户端不再观察到虚假的永久 `Failed`（[#2098](https://github.com/opensandbox-group/OpenSandbox/pull/2098)）
- 行为变更：Go、Kotlin 和 C# 中的后台命令结果收集在启动确认时返回，不再推断退出码为 0 —— 请查询命令状态以获得最终结果（[#1825](https://github.com/opensandbox-group/OpenSandbox/pull/1825)）
- 行为变更：多租户模式下，共享命名空间中其他租户的带标签 sandbox 现在解析为 404；未打标签的旧 sandbox 在过期前保持可见（[#1973](https://github.com/opensandbox-group/OpenSandbox/pull/1973)）
- Chart：`base` chart 现在默认创建共享的 `fastSandbox.namespaces.system` 命名空间 —— 如果你在外部管理它，请设置 `fastSandbox.namespaces.createSystem=false`（[#2044](https://github.com/opensandbox-group/OpenSandbox/pull/2044)）；ingress gateway 在 Kubernetes 部署中是必需的且必须安装在 server 之前，fast-sandbox 模式在渲染时需要 secure-access 密钥环（[#2047](https://github.com/opensandbox-group/OpenSandbox/pull/2047) [#2048](https://github.com/opensandbox-group/OpenSandbox/pull/2048)）
- Fast-sandbox 运维人员：恢复不再启动内核，直接启动需要操作者显式固定 `kernelPath`（[#2028](https://github.com/opensandbox-group/OpenSandbox/pull/2028)）；Firecracker 运行时现在在启动时要求带 reflink 的 XFS —— 在缺少它的节点上请使用提供的 reflink-XFS 状态盘辅助工具（[#2123](https://github.com/opensandbox-group/OpenSandbox/pull/2123)）；vendored CRD 移除了被删除的 `boxlite` 运行时枚举（[#2145](https://github.com/opensandbox-group/OpenSandbox/pull/2145)）；集成环境改为读取 `RUSTFS_*`/`RC_IMAGE` 而非 `MINIO_*`/`MC_IMAGE`，没有旧别名（[#2009](https://github.com/opensandbox-group/OpenSandbox/pull/2009)）

## 安装

```bash
# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.1.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# Before first install, configure the server API key and enable the ingress
# gateway (required on Kubernetes; the bare render disables it, and the server
# refuses to start with an empty api_key) — see the deployment guide:
# https://open-sandbox.ai/deployment/
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.1.1            # Python
npm install @alibaba-group/opensandbox@1.1.1   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.1.1")
dotnet add package Alibaba.OpenSandbox --version 1.1.1
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.1.1

# Run the server locally
uvx opensandbox-server==1.1.1
```

对照 BOM 验证你安装的内容：参见[发布验证](https://open-sandbox.ai/community/release-verification)。
