# OpenSandbox 1.1.1-rc.1

1.1.1 补丁版本线上的首个候选版本，用于修复损坏的 `1.1.0` server wheel：hatchling 的 VCS 排除过滤将已提交的 FastPath gRPC 桩（stub）从 PyPI 包中静默丢弃，导致所有 `1.1.0` 版本的 `opensandbox-server` 安装在导入时报错 —— PyPI 不可变，因此修复落在 `1.1.1` 补丁线上（[#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)）。除该修复外，本 rc 携带了自 `release-1.1.0` 以来合并的一切：agent-sandbox 暂停/恢复、共享命名空间的租户隔离、由 watch 驱动的创建延迟优化、`commands.setEnv` 以及对全部五个 SDK 的系统性审计清理、egress 的上游代理链，以及两次 fast-sandbox 固定版本提升。每个章节的基线均为 `release-1.1.0`。rc 发布镜像但暂扣软件包 —— SDK/CLI 制品随 `1.1.1` 稳定版本发布。请测试并报告问题。

## 亮点

- 修复 `1.1.0` server wheel：FastPath 桩现已随包交付，安装后可正常导入（[#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)）
- Server：agent-sandbox provider 上的暂停/恢复、共享 Kubernetes 命名空间中 sandbox 的租户隔离，以及由 watch 事件（而非 1 秒轮询）唤醒的 pool 创建（[#1975](https://github.com/opensandbox-group/OpenSandbox/pull/1975) [#1973](https://github.com/opensandbox-group/OpenSandbox/pull/1973) [#1996](https://github.com/opensandbox-group/OpenSandbox/pull/1996)）
- SDKs：全部五种语言中的 `commands.setEnv` 运行时环境变量注入，外加一次系统的跨语言审计清理，修复数十个正确性缺陷（[#2013](https://github.com/opensandbox-group/OpenSandbox/pull/2013) [#2020](https://github.com/opensandbox-group/OpenSandbox/pull/2020)）

## Server

- 通过桥接到 `agents.x-k8s.io/v1beta1` 上的 `spec.operatingMode`（`Running`/`Suspended`）实现 agent-sandbox provider 的暂停/恢复，具备状态推导（`Paused`/`Pausing`/`Resuming`/`Terminated`）、resourceVersion 前置条件，以及无效转换时的 409；此前两个端点均返回"不支持"（[#1975](https://github.com/opensandbox-group/OpenSandbox/pull/1975)）
- 隔离共享同一 Kubernetes 命名空间的租户：创建时打上 `opensandbox.io/tenant` 标签，list/get/delete/pause/resume/proxy 会以 404 隐藏其他租户的带标签 sandbox，而未打标签的旧 sandbox 在过期前保持可见；同时新增用于 ServiceAccount CA 不匹配场景的 `kubernetes.insecure_skip_tls_verify`（[#1973](https://github.com/opensandbox-group/OpenSandbox/pull/1973)）
- 修复多租户模式下 server 重启后续期意图（renew-intent）被静默丢弃的问题：解析器现在回退到集群级标签查询，配备 403 熔断器与结构化告警；在可验证时信任来自意图载荷中 ingress 观测到的命名空间；单租户部署的解析永远不会超出所配置的命名空间（[#1819](https://github.com/opensandbox-group/OpenSandbox/pull/1819)）
- 新增 `[docker] publish_host`，将桥接模式的 sandbox 端口发布到单个主机地址（默认 `0.0.0.0` 不变）—— 使用 `127.0.0.1` 或 Docker 桥接网关时，无令牌的 execd 端口不再落在公共网络接口上（[#1954](https://github.com/opensandbox-group/OpenSandbox/pull/1954)）
- 新增类型化、仅管理员可用的 `[egress.upstream_proxy]` 配置节（URL + 可选授权，加载时校验），在 Docker 和 Kubernetes 上为 sidecar 注入链式上游 CONNECT 代理；当所请求的 `networkPolicy` 不兼容时以 fail-closed 的 400 拒绝；密钥值不再在配置校验错误中被回显（[#1999](https://github.com/opensandbox-group/OpenSandbox/pull/1999)）
- 在模板创建时接受 `env` 并将其烘焙进 fast-sandbox 黄金镜像（`/etc/sandbox-init.env`，继承源镜像的 OCI `Config.Env`），弥补了 `SandboxTemplate.spec.envs` 存在但生命周期 API 拒绝它的缺口；全部 SDK 均支持（[#1984](https://github.com/opensandbox-group/OpenSandbox/pull/1984)）
- Kubernetes 创建等待改由 informer watch 事件唤醒，而非固定的 1 秒轮询，将预热 pool 的创建延迟从约 1 秒降至数十毫秒，同时保留轮询回退（[#1996](https://github.com/opensandbox-group/OpenSandbox/pull/1996)）
- 通过强制包含绕过 hatchling 的 VCS 排除，将已提交的 FastPath gRPC 桩打进 server wheel，并在发布工作流中于发布前对构建出的 wheel 做冒烟导入 —— 这就是 `1.1.0` 安装期损坏的修复（[#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)）
- 修复 Helm RBAC 和 fsb 快照运行时中 Fast Sandbox 快照 CR 的复数形式（`sandboxsnapshots`），此前 `sandboxesnapshots` 可能因缺少 RBAC 而导致 list/watch 失败（[#1972](https://github.com/opensandbox-group/OpenSandbox/pull/1972)）
- 将底层 FastPath 错误消息穿透到 429 容量映射中（保留状态与 `Retry-After`，新增 `cause` 字段），使准入/运行时故障（如 KVM 设备损坏）不再被掩盖为 pool 容量耗尽，并在映射前以 warn 级别记录原始错误（[#2001](https://github.com/opensandbox-group/OpenSandbox/pull/2001)）
- 修复 Docker 边缘情况：对已暂停 sandbox 的重复暂停请求按文档返回 409，而不是把 Docker 的"已暂停"以 500 呈现（[#2023](https://github.com/opensandbox-group/OpenSandbox/pull/2023)）；仅对选择启用隔离扩展的 sandbox 清除 Docker 的 masked/只读系统路径，使嵌套的 Bubblewrap 能挂载私有 procfs（[#1982](https://github.com/opensandbox-group/OpenSandbox/pull/1982)）

## SDKs

以下代码变更将随 `1.1.1` 稳定发布交付 —— rc 不发布 SDK 软件包。

- 在全部五个 sandbox SDK（Python async/sync、JavaScript、Kotlin/Java、Go、C#）中新增 `commands.setEnv`，用于持久化的运行时环境变量注入：以运行时精确的序列化将 `KEY=VALUE` 追加到 sandbox env 文件，进行本地 key/NUL 校验，并在 `EXECD_ENVS` 未设置时大声失败（[#2013](https://github.com/opensandbox-group/OpenSandbox/pull/2013)）
- 跨 sandbox、code-interpreter 和 MCP SDK 的系统性跨语言审计清理：Go 重试退避坍缩为零延迟且丢失会话 `cwd`；Python 隔离会话忽略 `encoding` 且就绪预算报告过期错误；JS resume 共享并杀死源 sandbox 的传输；Kotlin codes 运行丢弃所有 SSE 帧事件且从不设置 `exitCode`；C# create 在全新 sandbox 404 时失败且空响应体引发 NRE；MCP 的按调用关闭会拆除 server 级共享传输 —— 每一项都附带回归测试修复（[#2020](https://github.com/opensandbox-group/OpenSandbox/pull/2020)）
- 全部五个 SDK 支持模板创建时的 `env`，与 server 端的黄金镜像烘焙保持一致（[#1984](https://github.com/opensandbox-group/OpenSandbox/pull/1984)）
- 跨语言对齐后台命令流完成语义：随着 execd 移除固定的完成延迟，Go、Kotlin 和 C# 中的后台结果收集现在与 Python 和 JavaScript 一样在启动确认时返回，而不是等待 EOF 并推断退出码为 0 —— 请查询命令状态以获得最终结果；前台调用对旧 server 仍读取到 EOF（[#1825](https://github.com/opensandbox-group/OpenSandbox/pull/1825)）

## Controller

- 修复 image-committer 死锁：通过 cgroup v2 freeze 暂停 QEMU 容器时永远无法完成（KVM worker 内核线程永远到不了 `frozen`），修复方式是对已通过 QMP 暂停的 QEMU 容器跳过冗余的 freeze，并以 `--pause=false` 提交（[#1986](https://github.com/opensandbox-group/OpenSandbox/pull/1986)）

## Execd

- 移除命令完成后固定的 1 秒延迟，将终端事件到返回的中位延迟从约 1000 ms 降至亚毫秒级，同时保留输出冲刷和心跳清理（[#1825](https://github.com/opensandbox-group/OpenSandbox/pull/1825)）
- 在 bwrap 隔离层中支持每个会话多个独立 overlay 挂载（workspace 与系统路径分离的 upper、嵌套遮蔽、临时 tmpfs upper）；内部地基，无公共 API 变更 —— 请求级的 `overlays` 字段随后跟进（[#2021](https://github.com/opensandbox-group/OpenSandbox/pull/2021)）
- 停止在 info 级别记录每一个 stdout/stderr 数据块 —— 在输出密集的工作负载中它占 execd 日志量的 99.8%（[#1906](https://github.com/opensandbox-group/OpenSandbox/pull/1906)）

## Networking

### egress

- 在透明 mitmproxy 路径上新增可选的链式上游 CONNECT 代理（`OPENSANDBOX_EGRESS_UPSTREAM_PROXY`/`_AUTH`），将 sandbox 出站流量经企业正向代理路由，保持 SNI/Host 一致的 CONNECT authority，具备 fail-closed 的启动校验，未设置时行为不变（[#1816](https://github.com/opensandbox-group/OpenSandbox/pull/1816)）
- 继续凭证绑定的 TLS 拦截基础（OSEP-0023）**[EXPERIMENTAL]**：在 sidecar 启动和重启时于内部门禁之后 bootstrap 已认证的修订会话（[#1948](https://github.com/opensandbox-group/OpenSandbox/pull/1948)），以"先确认后发布"的提交语义暂存未发布的 Credential Vault 变更候选（[#1980](https://github.com/opensandbox-group/OpenSandbox/pull/1980)），在共享的变更屏障之后对 `/policy` 与 Vault 写入做串行化（[#1991](https://github.com/opensandbox-group/OpenSandbox/pull/1991)），在发布前暂存 always 规则重载（[#1997](https://github.com/opensandbox-group/OpenSandbox/pull/1997)），在协调器结果不确定时保留精确的尝试身份（[#2007](https://github.com/opensandbox-group/OpenSandbox/pull/2007)），并新增具备精确尝试调和的 bootstrap 后修订更新（[#2017](https://github.com/opensandbox-group/OpenSandbox/pull/2017)）—— 仅为地基；门禁之下公共 Vault 写入仍返回 503，选择性 TLS 保持禁用

### ingress

- 通过 `OpenSandbox-Access-Renew: skip` 头支持按请求退出访问续期意图，在触碰节流状态之前即被抑制，并在 gateway 和 server 代理两条路径上被剥离 —— 适用于健康探测和其他心跳式流量（[#1966](https://github.com/opensandbox-group/OpenSandbox/pull/1966)）

## Fast Sandbox

- Chart：新增 controller tolerations、一个 `sandboxtemplateBuilderPodSpec` PodSpec 片段 ConfigMap（合并进黄金镜像构建 Pod）、一个 `fastletProxyImage` 覆盖项（使注入的 sidecar 不必来自 docker.io），以及面向带污点或受限 registry 集群的 agent/janitor 运行时资源（[#1968](https://github.com/opensandbox-group/OpenSandbox/pull/1968)）
- 两次提升固定的 fast-sandbox 源码：`f45bc60` 为较旧的 API server 移除 CRD CEL 校验、使 P2P 在 peer-gateway 接缝之后可选、并让模板 guest 继承源镜像的 OCI env（[#1989](https://github.com/opensandbox-group/OpenSandbox/pull/1989)）；`2b5e840` 移除节点侧 guest 内核资产（`kernelPath` 变为可选）、新增快照 CPU 模板兼容性准入、并在恢复前将受限的 `/dev/kvm` 重新绑定到主机设备号（[#2028](https://github.com/opensandbox-group/OpenSandbox/pull/2028)）；中间的 `fb87a53` 将构建器的默认 guest 内核提升到 6.18.36（[#1992](https://github.com/opensandbox-group/OpenSandbox/pull/1992)）

## 其他（Misc）

- CLI：新增模板与快照管理（`osb template create|get|list|delete`、`osb snapshot ...`，以及在 `sandbox create` 上新增 `--template`/`--snapshot-id`）（[#2002](https://github.com/opensandbox-group/OpenSandbox/pull/2002)），为 `sandbox create` 和 `template create` 新增 kubectl 风格的 `-f/--file` 请求文件，覆盖完整线上格式并严格拒绝未知字段（[#2019](https://github.com/opensandbox-group/OpenSandbox/pull/2019)），并修复 `sandbox metrics --watch` 在 execd 原始 SSE 字段名上的失败（[#1970](https://github.com/opensandbox-group/OpenSandbox/pull/1970)）
- Chart：修正 chart 元数据，将镜像标签默认值统一为 `release-<appVersion>` 回退，使 `imagePullPolicy` 可配置，在 `helm.sh/resource-policy: keep` 下保留 dataplane Namespace，并围绕伞形发布流程以明确的安装顺序重写部署指南（[#2006](https://github.com/opensandbox-group/OpenSandbox/pull/2006)）
- Fast-sandbox 工具链：新增自托管的 KVM 集成测试工作流（[#1978](https://github.com/opensandbox-group/OpenSandbox/pull/1978) [#1985](https://github.com/opensandbox-group/OpenSandbox/pull/1985)）、一个为 Firecracker 供给预分配 reflink-XFS 状态盘的辅助工具（[#1995](https://github.com/opensandbox-group/OpenSandbox/pull/1995)）、一个贴近真实的黄金镜像测试工作负载（[#1983](https://github.com/opensandbox-group/OpenSandbox/pull/1983)），并在集成环境中以 RustFS 替换 MinIO（[#2009](https://github.com/opensandbox-group/OpenSandbox/pull/2009)）
- 文档：发布带实测创建/快照/恢复数据的 fast-sandbox 性能页面（[#1951](https://github.com/opensandbox-group/OpenSandbox/pull/1951) [#1992](https://github.com/opensandbox-group/OpenSandbox/pull/1992)），打磨 README 简介与 Features（[#1960](https://github.com/opensandbox-group/OpenSandbox/pull/1960)），修复文档重构导致的断链（[#1957](https://github.com/opensandbox-group/OpenSandbox/pull/1957)），将 OSEP-0016 标记为已实现（[#1955](https://github.com/opensandbox-group/OpenSandbox/pull/1955)），新增 DeerFlow 集成示例（[#2011](https://github.com/opensandbox-group/OpenSandbox/pull/2011)），并移除无人维护的 NullClaw 示例（[#2016](https://github.com/opensandbox-group/OpenSandbox/pull/2016)）
- release：将平台版本跨 chart 和镜像引用提升到 `1.1.1-rc.1`

## 升级与兼容性

- PyPI 上的 `1.1.0` server 包在导入时即损坏且无法替换（PyPI 不可变）—— 请升级到本版本线；参见 [#1959](https://github.com/opensandbox-group/OpenSandbox/pull/1959)
- 行为变更：Go、Kotlin 和 C# 中的后台命令结果收集在启动确认时返回，不再推断退出码为 0 —— 请查询命令状态以获得最终结果（[#1825](https://github.com/opensandbox-group/OpenSandbox/pull/1825)）
- 行为变更：多租户模式下，共享命名空间中其他租户的带标签 sandbox 现在解析为 404；未打标签的旧 sandbox 在过期前保持可见（[#1973](https://github.com/opensandbox-group/OpenSandbox/pull/1973)）
- Fast-sandbox 运维人员：`2b5e840` 固定版本移除了捆绑的节点侧 guest 内核 —— 恢复不再启动内核，直接启动需要操作者显式固定 `kernelPath`（[#2028](https://github.com/opensandbox-group/OpenSandbox/pull/2028)）；集成环境改为读取 `RUSTFS_*`/`RC_IMAGE` 而非 `MINIO_*`/`MC_IMAGE`，没有旧别名（[#2009](https://github.com/opensandbox-group/OpenSandbox/pull/2009)）
- 镜像：`opensandbox/<component>:release-1.1.1-rc.1`（全部三个仓库）
- 软件包：不变 —— SDK/CLI 制品随 `1.1.1` 稳定发布交付
- Chart：从该标签渲染（`helm template ./manifests/charts/opensandbox`）
- Kubernetes：支持范围 v1.21 – v1.34（chart 声明 `kubeVersion: ">=1.21.1-0"`）
- 版本偏差：server ↔ CLI/SDK 同一版本线受支持；±1 个 minor 会告警

## 安装

```bash
# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
git checkout release-1.1.1-rc.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag
```

对照 BOM 验证你安装的内容：参见[发布验证](/community/release-verification)。
